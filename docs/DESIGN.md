# 设计与迭代

## v1.0：技术面解读闭环

目标用户：不会阅读技术指标、希望理解近期历史走势的个人用户。

请求流：代码校验 → 行情适配 → 日期/复权/数据质量检查 → 指标 → 交叉事件 → 规则解释 → 图表定位。服务器不接受任意目标 URL，避免行情接口成为开放代理。

第一版选择 Node.js 单服务、原生模块和 SVG：无任务队列、无数据库，模型为可选外部调用，保持安装简单。单次请求有20秒源请求超时，最多4个并发任务；缓存最多100证券、5分钟。下载 JSON 用于保存分析快照，不在服务端保存个人历史。

信号与图表采用同一批数据。金叉前日 DIF≤DEA、当日 DIF>DEA，死叉相反。中期状态依据价格相对MA60的位置与MA60较5日前的方向。量能只作描述，不给出独立的买卖推荐。

数据限制：当前用非官方 Yahoo 接口验证三个市场，不能承诺全部证券覆盖。排除交易所当地今天是一种保守策略，不具备交易所完整日历及提前收盘识别；应在下一阶段用授权数据和交易日历替代。公司名称缺失时显示代码，不编造名称。

## 后续

1. 交易日历、明确可用的当日收盘确认、证券搜索和数据源适配接口。
2. 授权资讯源验证与事实引用的语义评估，不宣传未经测量的 AI 准确率。
3. 周线、信号后续表现与本地历史快照；先验证规则定义和边界。
4. 更丰富的无障碍图表与交互测试。无自动交易、荐股评级或未经验证的胜率。

## 深度解读与市场背景

保持原生前端和 Node 单服务，不新增依赖或环境变量。

1. 技术层：insight.js 计算 Wilder RSI14、ATR14 及排除分析当日的前 20/60 日高低点。RSI 首14次价格变化初始化，平盘为50，单向上涨/下跌为100/0；ATR 首根 TR 为高低差，之后包含相对前收盘的跳空。均是历史描述，不是反转保证。
2. 市场层：context.js 映射三个宽基指数，复用行情校验和缓存。用共同交易日期的5/20日首尾计算各自收益及百分点差；最后共同日必须等于个股截至日，不足21个共同日或请求失败时返回 unavailable，个股分析继续。暂不加入无可靠映射的行业比较。
3. 解读层：规则判断趋势与动能是否一致，再解释量能、RSI和历史观察位。DeepSeek 接收 technical、market、news 等事实，输出三段短文及引用；无 Key 或失败回退规则。事实 ID 校验和敏感表述拦截不是完整的语义验证。
4. 资讯层：按“资讯后续接入”的规划提供 not_configured 状态和空列表，不伪造接入。尚无经核验的授权源，不增加 Key、不抓取未知服务。未来需核验三市场覆盖、证券映射、时间戳与许可；条目必须具备标题、来源、原文 HTTPS 链接、发布时间与关联证券。未经核验，不向模型提供近期资讯。

请求链：个股行情（最多20秒）→ 指标与指数行情（最多20秒）→ 可选 DeepSeek（最多25秒）。最多4个分析请求；指数沿用5分钟缓存。页面单独展示市场、技术依据、资讯缺失状态，模型与规则明确区分，JSON导出包含完整响应。

不包含：行业行情、实时资讯接入、自动交易和信号后续回测。真实数据与模型可用性需独立验证，不将模拟测试作为实时验证。
